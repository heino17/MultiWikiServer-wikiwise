# AGENTS.md

Instructions for AI coding agents working in this repository — and for humans
who want the short version. They cover the things that are easy to get wrong.
Everything else lives in the documents linked at the end.

If a tool named here does not exist in your environment, ignore the tool name
and follow the rule behind it. The rules matter, the tool list does not.

## What this repository is

A maintained fork of `TiddlyWiki/MultiWikiServer`, published as
**MultiWikiServer-wikiwise** (`@mws/wikiwise`, BSD 3-Clause). TypeScript,
bundled with tsup, served through a TiddlyWiki5 plugin host. Two applications
matter:

- the MWS server: `packages/mws` (entry point), `packages/server`,
  `packages/commander` (CLI), `packages/events`, `prisma/` (data layer)
- the admin app: `packages/admin-vanilla` — `src/app.tsx` (routing),
  `src/list-view.ts` (shared code for all list tabs), `src/i18n.ts` with
  `src/locales/` (DE/EN), `src/app-*.tsx` (pages). TSX on
  `@tiddlywiki/jsx-runtime`; no React or preact.

The wiki-side client is `plugins/client`. Distribution happens through GitHub
Releases with a tarball attachment. **The fork is deliberately not published to
npm** — never run `npm publish`, never create or change npm packages, tokens,
orgs or accounts. `create-package/README.md` records why.

## Read before you change anything

1. `ARCHITECTURE.md` — how a wiki is assembled, request flow, trust
   boundaries, repository layout. Maintained for this fork.
2. `PLANNING.md` — open points, deliberately unfinished ideas (`◐`), and
   decisions already taken (`⚖️`). Do not silently re-open a `⚖️` entry.
3. `CHANGELOG.md` — every change of this fork has a numbered section `§N` that
   also records the *why*. `grep -n "§12" CHANGELOG.md` is the fastest way to
   understand a piece of code before you touch it.

## Hard rules

- **Never edit `dist/`.** It is generated by tsup and git-ignored.
- **TiddlyWiki files are not Markdown.** `editions/**/tiddlers/*` uses `.tid`
  and `.multids` syntax, and `editions/bedienungsanleitung` is a wiki edition,
  not a Markdown site. Do not "fix" formatting there.
- **New user-visible strings need both languages.** Use `t("...")` and add the
  German and the English entry; the admin app is bilingual by contract.
- **Documentation is bilingual by contract.** `README.md`,
  `README_features.md` and `CHANGELOG.md` each carry an English and a German
  half with the same structure. A new section goes into both halves.
- **The CHANGELOG is the development story.** Every user-visible change gets a
  new numbered section (`§86` is next), newest first, with the same number in
  both language halves. Inline code, identifiers, file names and command lines
  stay literally identical across halves; prose is wrapped at about 80 columns.
- **Do not weaken the security invariants** (`ARCHITECTURE.md`,
  `PLANNING.md`): the referer check in `RequestState.ts` (deliberately a
  prefix test), the per-wiki CSP from `RecipeResolver.ts`, public read access
  only via the `ANON` role, and read-only wikis must never save.
- **No silent dependencies.** Check whether the project already ships something
  similar before adding a library, and say so in your summary.
- **Never commit secrets.** A session token lives in `~/.npmrc`; it must never
  end up in a diff, a log, a test fixture or the repository.
- **Never push, tag, publish or bump a version unless asked.** Editing and
  committing when you were asked to change something is fine; everything that
  leaves the machine stays an explicit decision of the maintainer.
- **Side tangents are comments first.** If the maintainer changes subject or
  starts a side tangent, treat it as a comment and answer it instead of
  starting to edit files for it.

## Commands

| Goal | Command | Notes |
|---|---|---|
| Install | `npm install` | Also runs `prepare` → `build:pack`, so the first install builds everything. `npm run install-android` for Android/NDK. |
| Develop (watch) | `npm start` | tsup in watch mode, then `mws.dev.mjs`; dev wiki on <http://localhost:8080/>, data folder `dev/wiki`, listeners and TLS in `mws.dev.mjs`. |
| One-off CLI task | `npm start init-store`, `npm start update-tiddlywiki`, … | Everything after `start` is passed to the MWS CLI. |
| Documentation site | `npm run docs` | `npm start` plus the docs route. |
| Production build | `npm run build` | Client bundle, then the runtime bundle into `dist/`. |
| Typecheck server | `npm run tsc2` | `tsc --noEmit`. The root script `npm run tsc` is a tsup variant, not the typechecker. |
| Typecheck admin app | `cd packages/admin-vanilla && npm run tsc` | The root script `npm run tsc-client` still points at the removed `packages/react-admin` and fails. |
| Wiki-side client | `npm run build:client` | esbuild bundle + `tsc` in `plugins/client`. |
| Fresh instance from the tarball | `npm test` | Builds, `npm pack`, wipes and recreates `tests/`, installs the tarball there and **starts a server on port 8080** — stop the dev server first. Smoke test, no automated assertions. |
| Reset the dev store | `npm run dev-quick-reset` | Deletes `dev/wiki/store`, re-runs `init-store`. |
| Local HTTPS | `npm run certs` | Unix only, writes `localhost.*`. |
| Prisma client | `npm run prisma:gen` | Validate, format, generate. |
| New migration | `npm run prisma:mig` | `prisma migrate dev --create-only` against `DATABASE_URL=file:test.sqlite`. |

The database comes from `DATABASE_URL` (SQLite, Postgres, MSSQL); schema in
`prisma/schema.prisma`, migrations in `prisma/migrations`, older ones in
`prisma/migrations-v1`. Stores created before 27.09.2026 need the additional
tables — read §70 before touching an old store.

## Conventions

- Commits: one topic each, small, `feat:` / `fix:` / `refactor:` / `docs:` /
  `style:` / `release:` / `chore:` with **German message text** and the
  CHANGELOG reference in parentheses, e.g.
  `feat: Suche und Sortierung in allen fünf Listen-Tabs (§78)`.
- Code style: follow the surrounding file. TypeScript everywhere; no framework
  in the server packages.
- Do not stage generated or local artifacts: `dist/`, `*.tgz`, `dev/wiki/`,
  `tests/`, `store/`, `test.sqlite`, `.env`, `localhost.*`. `.gitignore` covers
  them; the `packages/mdui-admin` exception in it is stale.
- Verification is manual. CI (`.github/workflows/ci.yml`) only builds the
  documentation site on pushes to `main`; there is no automated test suite. Run
  the dev instance, click through the change in a browser, and write down what
  you saw in the CHANGELOG section.

## Before a change counts as done

- [ ] `npm run tsc2` is clean and `npm run build` succeeds
- [ ] verified in a dev instance — state in the §-section what you clicked and
      what you observed
- [ ] new CHANGELOG section in **both** language halves, identical §-number
- [ ] `README.md` / `README_features.md` updated if the change is user-visible
- [ ] new UI strings exist in DE and EN
- [ ] `git status` shows nothing generated
